банка: суммы денег лежат на счетах, клиенты хранятся в таблице, а всё
состояние сохраняется в JSON-файл и читается обратно.

## Принципы ООП в проекте

| Принцип | Как применён |
|---------|--------------|
| Классы, объекты, конструктор `__init__` | каждый класс проверяет аргументы в `__init__`: нельзя создать `Money(10.5)` или таблицу с повторяющимися столбцами |
| Инкапсуляция | баланс счёта хранится в `_balance` и доступен только для чтения через `property`; менять его можно лишь методами `deposit`, `withdraw`, `transfer`, которые проверяют сумму и валюту |
| Наследование | `SavingsAccount` наследует `BankAccount` и добавляет неснижаемый остаток и проценты |
| Полиморфизм | `SavingsAccount` переопределяет `_check_can_withdraw`, поэтому один и тот же вызов `withdraw` ведёт себя по-разному для разных счетов (см. `tests/test_savings.py::test_polymorphic_withdraw_check`) |
| Перегрузка операторов | `Money` реализует `+`, `-`, унарный минус, сравнения и `__radd__` для `sum()` |

## Отчёт о выполнении

### Задание 7 (средней сложности): перегрузка оператора +

`Money` хранит сумму целым числом копеек, поэтому `0.1 + 0.2` здесь не
превращается в `0.30000000000000004`. Метод `__add__` складывает суммы
одной валюты и возвращает новый объект (исходные не меняются), для
чужих типов возвращает `NotImplemented`, а `__radd__` позволяет
считать `sum()` по списку сумм. Сложение рублей с долларами даёт
`ValueError`.

```python
price = Money.from_string("1250.50")
delivery = Money.from_string("99.50")
total = price + delivery        # Money(135000, 'RUB')
```

```console
== Перегрузка оператора + ==
1250.50 RUB + 99.50 RUB = 1350.00 RUB
sum(['100.00 RUB', '25.50 RUB', '0.45 RUB']) = 125.95 RUB
RUB + USD -> ValueError: разные валюты: RUB и USD
```

### Задание 3 (средней сложности): класс «Банковский счёт»

`BankAccount` поддерживает пополнение (`deposit`), снятие (`withdraw`) и
перевод (`transfer`), ведёт историю операций. Неположительная сумма,
другая валюта или не `Money` отклоняются; при нехватке средств
возбуждается собственное исключение `InsufficientFundsError`, а
баланс не меняется. Перевод сначала проверяет сумму для счёта
получателя, поэтому при ошибке деньги не списываются.
`SavingsAccount` добавляет неснижаемый остаток и начисление
процентов с округлением до копейки.

```console
== Банковский счёт ==
после пополнения и снятия: 11799.25 RUB
снятие 50000 -> InsufficientFundsError: на счёте 11799.25 RUB, а списать нужно 50000.00 RUB
перевод 8000: карта 3799.25 RUB, вклад 8000.00 RUB
начислено процентов: 120.00 RUB
снятие 7500 со вклада -> отказ: нельзя опустить баланс ниже 1000.00 RUB
  вклад: пополнение  8000.00 RUB
  вклад: проценты    120.00 RUB
```

### Задание 9 (средней сложности): класс для работы с файлами

`TextFile` оборачивает путь к файлу: `read`, `read_lines`, `write`,
`append`, `append_line`, `exists`, `size`, `delete`. Кодировка задаётся
в конструкторе. `write` создаёт недостающие каталоги и пишет данные
сначала во временный файл, а затем атомарно заменяет им исходный, —
при сбое записи старое содержимое не портится. В демонстрации через
`TextFile` сохраняется и читается состояние банка (см. ниже).

### Задание 5 (повышенной сложности): сериализация объектов в JSON

`JsonSerializer` сохраняет объект как словарь его атрибутов с полем
`"__type__"` и восстанавливает его без вызова `__init__`. Создавать
можно только классы, зарегистрированные методом `register`, — в отличие
от `pickle`, из подменённого JSON нельзя получить произвольный объект.
Отдельно сохраняются типы, которых нет в JSON: `tuple`, `Decimal` и
словари с нестроковыми ключами (например, строки таблицы по `id`),
поэтому после восстановления объекты полностью рабочие.

```console
== Сериализация в JSON и работа с файлом ==
записано символов: 4181, файл bank_state.json
восстановлено: BankAccount('Фадеев И. А.', '40817-0001', balance=3799.25 RUB)
восстановлено: SavingsAccount('Фадеев И. А.', '42301-0002', balance=8120.00 RUB)
история вклада совпадает: True
строки таблицы совпадают: True
```

### Задание 7 (повышенной сложности): мини-ORM

Таблица описывается списком столбцов `Column(имя, тип, required,
default)`, тип задаётся строкой (`"int"`, `"float"`, `"str"`, `"bool"`),
чтобы описание можно было сохранить в JSON.

- `insert(**значения)` проверяет имена и типы столбцов, подставляет
  значения по умолчанию, присваивает автоматический `id` и возвращает
  его. При ошибке строка не добавляется.
- `select(where=None, *, order_by=None, descending=False, limit=None,
  **равенства)` отбирает строки по равенству столбцов и функции-условию,
  сортирует (пустые значения — в конце) и ограничивает количество.
  Возвращаются копии строк, поэтому изменить таблицу в обход `insert`
  нельзя.

```python
clients.select(city="Москва", order_by="age")
clients.select(lambda row: row["age"] >= 30, order_by="name")
```

```console
== Мини-ORM ==
Table('clients', rows=4)
клиенты из Москвы по возрасту:
  {'id': 4, 'name': 'Анна', 'city': 'Москва', 'age': 19, 'vip': False}
  {'id': 1, 'name': 'Иван', 'city': 'Москва', 'age': 21, 'vip': True}
  {'id': 3, 'name': 'Олег', 'city': 'Москва', 'age': 45, 'vip': False}
старше 30: ['Мария', 'Олег']
insert с age='сорок' -> TypeError: столбец age ожидает int, получено str
```
